# ADR-0018: Mirror the sbx "balanced" network policy as the msb default egress baseline

## Context

sbx ships a **`balanced`** network policy that allows a broad, curated set of
developer hosts (AI services, package registries, code/container hosts, cloud
infrastructure, OS package mirrors, and certificate-validation endpoints) while
blocking everything else. It is the recommended sbx default, and the sbx path in
this repo assumes it (`docs/QUICKSTART_SBX.md`).

msb (microsandbox) has **no** equivalent default. Its low-level network model is
deny-by-default with an ordered rule list, and its high-level profiles
(`public`, `private`, `host`) do not correspond to the sbx `balanced` host set.
Left alone, an msb sandbox created by `acq` reaches only the hosts the four
built-in kits declare in `caps.network.allow` (`api.gsa.usai.gov`,
`api.github.com`) plus the npm registry added when an agent is installed —
dramatically more locked down than the equivalent sbx sandbox. A user who runs
`pip install`, `cargo build`, `apt-get`, etc. inside an msb sandbox would fail on
egress that "just works" on sbx.

The sbx `balanced` host list is generated by the sbx daemon; it is **not** stored
in this repo and cannot be read at msb-create time without sbx installed on the
host (which, on an msb-only machine, it is not).

## Decision

Give every msb sandbox the **same egress as the sbx `balanced` policy by
default**, composed on top of the kits' own `caps.network.allow`.

1. **Vendored host list.** Add `acq.backends/msb-balanced-hosts.txt` — a
   human-auditable, `#`-commentable file whose non-comment lines are a
   **verbatim mirror** of the `host:port` rows from `sbx policy inspect
   local-policy`. This file is the single source of truth an operator edits when
   sbx `balanced` changes. Keeping it a faithful mirror (no pre-translation)
   makes it trivially diffable against fresh `sbx policy inspect` output.

2. **Translation in one place.** The msb adapter
   (`_acq_msb_balanced_rules_into`, with helpers `_acq_msb_balanced_target` /
   `_acq_msb_balanced_port_ok`) translates each entry into an msb `--net-rule`
   per the msb grammar (`allow[:egress]@<target>[:<proto>[:<ports>]]`):
   - `**.host` (sbx multi-label glob) and `*.host` → msb domain-suffix `*.host`
     (msb suffixes match the apex and any subdomain at any depth, so collapsing
     `**.` → `*.` loses no coverage).
   - `:PORT` → `:tcp:<port>` (sbx `balanced` is TCP; a host listed on both `:80`
     and `:443` yields **two** rules, preserved per-port).
   - `crl*.digicert.com` (an intra-label glob msb **cannot** express) → broadened
     to the parent suffix `*.digicert.com`, with a one-time warning recording the
     widening. This preserves CRL / certificate-revocation reachability on `:80`,
     a real TLS-path dependency, at the cost of a slightly wider match than sbx.
   - A leading `allow@dns` rule is emitted so the guest can resolve the allowed
     hosts — under `--net-default deny` the high-level DNS auto-grant does not
     apply, so DNS must be granted explicitly. This pairs with the existing
     `--dns-nameserver`.

3. **Restrict, don't merely widen.** At create, when the baseline is enabled the
   adapter emits `--net-default deny` **plus** the generated `allow@…` rules, so
   egress is *restricted to* the balanced set (deny-by-default + allowlist) —
   genuine parity with sbx `balanced`, not "allow-all with extras". The kit, npm,
   and secret-binding rules are all `allow@…` and compose correctly under the
   deny default.

4. **Toggle, on by default.** `ACQ_MSB_BALANCED_EGRESS` (default on) enables the
   baseline; `0`/`false`/`no`/`off`/empty (case-insensitive) disables it and
   falls back to kit-only egress (no `--net-default deny` is emitted in that
   mode). `ACQ_MSB_BALANCED_HOSTS_FILE` overrides the list path for a
   site-specific set.

## Consequences

- **Better:** msb sandboxes reach the same dev hosts as sbx sandboxes out of the
  box; `acq` behaves consistently across backends. The host set is auditable at a
  glance and re-syncs by copy-paste from `sbx policy inspect`.
- **Security posture (SC-7):** this *widens* the default msb egress (from
  kit-hosts-only to the full `balanced` set). That is the intent — parity with
  the sbx default the project already recommends — and it remains an **allowlist
  under deny-by-default**, not allow-all. The `crl*` broadening is the only place
  the msb set is intentionally wider than sbx; it is logged. Operators who need a
  tighter posture set `ACQ_MSB_BALANCED_EGRESS=0` (kit-only) or point
  `ACQ_MSB_BALANCED_HOSTS_FILE` at a narrower list.
- **Interaction with the npm-install allow-rule:** the adapter separately
  allow-lists the npm registry (`registry.npmjs.org`) only when installing an
  agent (ADR-0011). That host is ALSO in the `balanced` set, so with the baseline
  ON **every** sandbox — including a `shell` sandbox with no agent — can reach the
  registry, exactly as it can under sbx `balanced`. This is intended parity, not a
  leak: the agent-conditional npm gate still matters only in kit-only mode
  (`ACQ_MSB_BALANCED_EGRESS=0`), where a `shell` sandbox gets no npm egress.
  Because kit `caps.network.allow` rules are emitted as broader bare `allow@host`
  (any proto/port) BEFORE the balanced block, a host present in both composes
  harmlessly under first-match-wins.
- **Untrusted-input hardening (SI-10):** the host list is semi-trusted data that
  drives create-time flags, so every translated target is charset-validated
  (`[A-Za-z0-9.*_-]`), single-label suffixes (`*.com`) are rejected (msb refuses
  them anyway — accidental blast radius), and every port is integer-validated
  (1..65535) before it reaches an argv via the eval-by-name append. Malformed
  lines are dropped with a warning; a missing/unreadable file is a non-fatal
  warning (kits still add their egress).
- **Tradeoff — drift:** the vendored file is a point-in-time snapshot of sbx
  `balanced`. When sbx updates its policy, this file goes stale until re-synced.
  Mitigated by (a) the provenance header in the file, (b) the re-sync procedure
  documented there and in `docs/KNOWN_FAILURE_MODES.md`, and (c) the quarterly
  re-verification cadence (per `AGENTS.md`).
- **Compliance:** no new external services; a configuration/adapter change only
  (CM-2/CM-6/CM-7; SA-8/SA-15). The secret-injection and TLS-interception model
  (SC-8) is unchanged.

## Alternatives considered

- **Derive from `sbx policy inspect` at runtime.** Always in sync, but requires
  sbx installed on the msb host (generally false on an msb-only machine) and
  couples the two backends at runtime. Rejected.
- **Author a new neutral "balanced-egress" kit** in `agentic-coding-patterns`
  whose `caps.network.allow` carries the list, consumed by both backends. The
  most architecturally consistent option, but it puts the list in the other repo,
  requires a cross-repo change plus a new pinned ref, and still needs the same
  msb wildcard/port translation. Deferred; the vendored file can migrate into
  such a kit later without changing the emitter.

## Verification

- Offline: `scripts/test-acq` covers target translation (`**.`, `crl*`, exact,
  single-label rejection), port validation, dual-port hosts, the DNS rule,
  malformed-line skipping, a full parse of the real vendored file with no skips,
  and the default-on / `=0`-off provision paths.
- Live (deferred; requires a KVM-capable host — cannot run inside a sandbox):
  create an msb sandbox and confirm a `balanced`-only host that no kit allows
  (e.g. `pypi.org:443`) is reachable while an unlisted host is refused. Run per
  the ADR-0011 periodic-validation cadence.
